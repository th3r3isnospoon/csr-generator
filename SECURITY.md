# Security

This application handles private keys locally. Never include real keys, passphrases,
PKCS#12 files, or confidential subject data in issue reports, logs, or screenshots.
Use disposable reproduction material.

Report a vulnerability privately through the repository's GitHub Security advisories
page if private reporting is enabled. If it is unavailable, open a minimal issue
requesting a private contact channel without exploit details or sensitive material.

The v1 implementation has known key-protection, shell-input, and correctness problems.
Prefer a reviewed v2 build once available. Do not assume a passphrase protected EC or
Ed25519 keys generated by v1. Review access to those keys and rotate affected keys when
appropriate for your deployment.

V2 does not protect against a compromised user account, administrators, insecure
clipboard managers, or malicious storage. Encryption at rest is enabled by default.
POSIX permissions are explicit; Windows removes inherited ACLs and applies a user SID
grant before writing secrets, failing closed when the OS tools cannot do so. Python and Tk cannot
guarantee zeroization. No certificate trust installation or network trust validation
is performed. Keep cryptography, Python/Tk, and optional OpenSSL patched.
